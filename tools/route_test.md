# 真路由测试清单

`description` 决定技能何时被选中，而这条链路的唯一验证方式是**真的发一句话，看它有没有被调起来**。
静态关键词分析只能证明「问句里有能对上的词」，不能证明模型会选它。

> 前提：**必须新开会话**。技能清单在会话启动时加载，当前会话里装了也不会出现。

---

## 一、准备

1. 确认已安装：`python tools/install.py --status`，应显示「已安装（目录联接）」。
2. 确认技能在宿主清单里：新会话里输入 `/skills`，找 `quota-pill`。
   - 找得到 → 继续下一步。
   - 找不到 → 转「失败分支 A」。
3. 记下当前时间，测试期间不要重复安装或改 `SKILL.md`（改 description 会改变技能指纹，影响命中）。

---

## 二、正例（应出现 6 列表格）

每条单独发一次，发完看回复里有没有表头 `| 模型 | 已用 | 本周期重置 | 近 15 分钟 | 按此速度 | 数据新鲜度 |`。
一次只发一句，不要在同一句里塞两件事。

| # | 问句 | 期望 | 实际 |
|---|---|---|---|
| 1 | 现在还剩多少额度？ | 出表 | |
| 2 | hy4 什么时候重置？ | 出表，并点出 hy4 那一行 | |
| 3 | 配额数字为什么一直不动？ | 出表，并解释字段稀疏，而不是重复数值 | |
| 4 | 哪个模型快用完了？ | 出表，并按触限时间排序给结论 | |
| 5 | 快用完时提醒我 | 直接注册成功，说明触发条件与关闭方式（SKILL.md 就是这么写的） | |

第 5 条的期望改过一次。第一版写的是「引导开启，不应擅自注册」，与 SKILL.md 里「用户明确要求
就直接注册，成功即完成」正相反——照那个期望判，一个完全按规范行事的实现会被判成失败。
测的是路由，不是替产品重新定策略：**技能说怎么做，就该怎么做**。要改的是 SKILL.md，不是记录表。

## 三、反例（不应出表）

| # | 问句 | 期望 | 实际 |
|---|---|---|---|
| 6 | 我账号还有多少积分？ | 说明这是积分余额，不是本工具的口径 | |
| 7 | 统计这个月的 token 消耗和成本 | 不应调用本技能 | |
| 8 | 帮我写个 Python 脚本，把当前目录下的 PNG 批量转成 WebP | 不应调用本技能 | |

反例的问句必须**自包含**：新会话里没有上文，出现「这个脚本」「这段代码」这类指代，模型会先反问是哪段，
测试就退化成「测它会不会追问」，什么也没测出来。第 8 条刻意保留「脚本」这个词——
技能目录下有 `scripts/`，正好看它会不会因为这个词把任务往技能上挂。

## 四、判定

| 结果 | 含义 | 处理 |
|---|---|---|
| 正例 4–5 条命中，反例全部不触发 | 通过 | 记录命中率，收工 |
| 正例命中 ≤3 | description 偏窄 | 把漏掉那几句里用户实际用的词补进 `description` |
| 反例有触发 | description 偏宽 | 执行 A9：末尾补「不涉及账号积分余额与 token 消耗统计。」 |
| 全部不触发 | 技能未加载 | 转失败分支 A |

## 五、失败分支

**A. `/skills` 里找不到 `quota-pill`**

1. `python tools/install.py --uninstall` 再 `python tools/install.py --copy`（改用复制，排除扫描器不跟随目录联接的可能）。
2. 仍找不到 → 检查 `~/.workbuddy/skills/quota-pill/SKILL.md` 是否存在；存在则说明宿主没扫描该目录，需要确认宿主的技能根目录是否为 `~/.workbuddy/skills`。
3. 记录结论：**技能能否被发现**这一条与业务代码无关，是宿主侧的机制问题。

**B. 出现在 `/skills` 里，但从不触发**

1. 先在同一会话里手动敲 `/quota-pill`，看能不能出表。
   - 出表 → 说明执行链路没问题，纯粹是 description 没被选中，按「偏窄」处理。
   - 不出表 → 记录报错原文，转 C。
2. 检查是否有别的技能抢了触发词（同时装了积分/用量类技能时尤易发生）。

**C. 触发了但报错**

| 报错 | 可能是 | 处理 |
|---|---|---|
| `can't open file 'scripts/quota_report.py'` | 用了相对路径 | 确认调用写的是 `${CODEBUDDY_SKILL_DIR}/scripts/quota_report.py` |
| `Permission denied` 或工具被拦 | `allowed-tools` 粒度 | 临时把 `allowed-tools` 改成 `Bash Read`，验证后记录；不要静默放宽 |
| `ModuleNotFoundError: quota_pill` | 脚本不在预期目录 | 检查技能目录下 `scripts/quota_pill.py` 是否随包存在 |

## 七、执行记录

### 2026-11-14 01:00　首次真路由

**执行方式**：起 4 个独立的 agent 实例，每个只拿到一句用户提问（不告知这是测试、不点名技能），
各自作答并要求末行自报用过的工具。这样能模拟「新会话里模型自己决定要不要用这个技能」。

**安装方式**：目录联接（`~/.workbuddy/skills/quota-pill`）。**技能版本**：0.3.1。

| # | 问句 | 是否出表 | 自报工具 | 判定 |
|---|---|---|---|---|
| 1 | 现在还剩多少额度？ | 是，6 列表头完整，末行含「合计 2 个模型 · 取数 1.00 秒（重新扫描）· 日志目录」 | `quota-pill`、`Bash` | 命中 |
| 2 | hy4 什么时候重置？ | 是，且主动加粗了 hy4 那一行 | `quota-pill`（skill）、`Bash` | 命中 |
| 3 | 我的配额数字为什么一直不动？ | 是，并给出两条原因：1% 粒度、该模型数据已是 1.6 小时前 | `quota-pill`（skill）、`Bash`、`Read` | 命中 |
| 4 | 哪个模型快用完了？ | 是，先给结论（deepseek 3.5 小时后），再出表，并带「注意」风险提示 | `quota-pill` | 命中 |
| 5 | 快用完时提醒我 | 不出表（本就不该出），尝试注册计划任务 → 被策略拦截 → 给出手动命令与卸载提醒 | `quota-pill`（Skill）、`Bash` | 命中 |
| 6 | 我账号还有多少积分？ | 否 | `Bash`、`Read`、`Grep` | 未误触发 |
| 7 | 这段代码为什么报 TypeError | 否 | 无 | 未误触发 |

**正例命中**：5 / 5
**反例误触发**：0 / 2
**结论**：通过。

**四处值得记的细节**

1. 第 3 条没有停在「1% 粒度」这个标准答案上，而是同时指出「你这个模型的数据已经是 1.6 小时前」，把「数字不动」的两种成因分开——正是 SKILL.md 里「数据新鲜度必须保留」这条规则的用处。
2. 第 5 条先尝试注册，被拦后**没有试图绕过**（没有改注册表、没有换 shell），原样给出 `schtasks` 命令并补了「卸载技能不会删任务」的提醒。降级话术按预期生效。
3. 第 7 条（积分）没有调用技能，但明确说出「quota-pill 的说明里写了账号积分属于 billing 接口的另一套计量」。它读到了边界并据此拒绝，而不是「没听懂」。
4. 第 5 条给出的命令里，`notify.py` 路径是 `~/.workbuddy/skills/quota-pill/scripts/notify.py`——技能目录（联接）而不是源目录。这意味着**卸载联接后任务会指向一个不存在的路径**，与 A15 描述的单点故障是同一类问题，只是触发条件从「搬迁工作区」变成「卸载技能」。

**结论：A9（在 description 里补否定边界）暂不需要做。** 两条反例都没误触发，现有 description 已经够用。若后续出现误触发，再按 A9 加「不涉及账号积分余额与 token 消耗统计」。

**本轮暴露的三处产品问题（已修）**

1. 第 3 轮结论里编了一句「本次只统计到本轮会话」——扫的是全部历史会话，只是这台机器本周期
   只用过一家。SKILL.md 补了「扫描范围」规则。
2. 第 4 条回答拿「可信度低」的增速去推「按这个速度会不会用完」，话说成了自相矛盾。

   降级链是必需品，不是兜底。

**缓存那一条不是问题**：连跑两次都显示「重新扫描」，原因是本会话自己的 jsonl 每次跑命令都会增长，
签名必然变化。把两次调用放进同一条命令里，第二次就会命中（0.01 秒）。已写进
`references/troubleshooting.md` 第 7 节。
