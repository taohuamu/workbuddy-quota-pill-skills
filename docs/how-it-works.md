# 运行逻辑

最后对照代码：2026-11-14（技能 0.4.2）

一句话：技能不是程序，是一份给模型看的说明书加一组只读脚本，由宿主在会话里按需唤起。
没有进程、没有窗口、没有服务、没有注册表项。

---

## 一、安装与加载

安装 = 把目录放进 `~/.workbuddy/skills/`，卸载 = 删掉。没有注册步骤。

宿主要在**会话启动时**扫一遍这个目录，把每个技能的 `name` 和 `description` 读进内存。
所以「装完当前会话没反应」不是缺陷，是加载时机：技能清单已经定型了，新装的要等下个会话。
包里给的 `install.py --copy` / 默认的目录联接，区别只在源目录能不能删——
联接指着工作区，改了即时生效；复制是快照，改了要重装。

---

## 二、五段链路

**1. 路由** —— 你发一句话，模型拿着所有技能的 `description` 自己判断要不要调。
整条链路里只有这一步是不确定的，其余四步都是确定性代码。这也是为什么
`tools/route_test.md` 必须真发问句：静态检查只能证明「问句里有能对上的词」，
证明不了模型会选它。

**2. 注入** —— 命中后宿主把 `SKILL.md` 全文塞进上下文，并把 `${CODEBUDDY_SKILL_DIR}`
替换成技能目录的绝对路径。所以 SKILL.md 里可以直接写变量，不必写死路径。
异机的会话归档里能看到实证：模型收到的正文里，变量已经是
`C:/Users/<用户名>/.workbuddy/skills/quota-pill`。

**3. 执行** —— 模型按「快速指导」跑 `quota_report.py`。必须绝对路径：工作目录在项目里，
不在技能目录，相对路径必然 `can't open file`。

**4. 数据层** —— `build_report()` 全量扫 `projects/*/*.jsonl`，逐行取
`providerData.rawUsage.quota`，按 `reset_at` 判断是否还在本周期，再用近 60 分钟的点算增速。

**5. 出表** —— 7 列 Markdown，末行固定带取数耗时与日志目录。模型只被允许原样贴、
补一句结论，不许重排行序、四舍五入改写数字、删末行。

---

## 三、数据层的三个判定

**周期归属。** `reset_at` 是字符串形式的 Unix 秒。它代表「下一次重置的时刻」，
本周期起点 = 它往前推 24 小时。`now > reset_at + 60s` 就判定为停在上一周期
（60 秒是抖动宽限），这些模型被过滤出表，只在末行报「另有 N 个停在上一周期」。
判据只看 `reset_at`，跟快照多久以前无关——一条两小时前的快照只要还没到重置时刻，
仍然算本周期，只是「数据新鲜度」会显示两小时前。

**增速与置信度。** 取近 60 分钟内的点做端点差分，按样本跨度分档：
跨度 ≥120 分钟且涨了 ≥3 格 → 高；≥30 分钟且 ≥1 格 → 中；其余 → 低。
百分比是整数，跨度太短会把速率放大好几倍，所以低置信度只提示、不告警。

**等级。** 按顺序判：已用 ≥95% → 触限；低/无置信度且已用 ≥80% → 按最坏打算；
低/无置信度 → 暂不预测（ETA 置空，不拿噪声外推）；预计触限早于重置 → 重置前就会耗尽；
预计 3 小时内触限 → 注意；其余 → 够用。排序固定为触限 → 注意 → 够用 → 暂不预测。

进程退出码只有两种含义：`1` 表示有模型处于触限等级（`--json` 里的 `has_risk`），
`0` 表示没有。**「注意」不算风险**，所以退出码 1 不是错误。

`verdict` 是数据层给表格用的完整句（"重置前就会耗尽"这种）。给用户显示时统一换成
「多久触限」一个口径，由 `scripts/phrasing.py` 一处完成，报告与通知都从那里取：
算得出时间就写「4.5 小时内触限」，算不出写「即将触限」，样本不足写「无法预测触限时间」，
撑得到重置写「剩余额度充足」。**只换说法，不改判定**——等级永远是 `quota_watch` 定的。

## 四、缓存

按「日志文件集合 + 纳秒 mtime + 大小」签名，TTL 300 秒，缓存文件在
`%LOCALAPPDATA%\quota-pill\skill-cache.json`。

它在活跃会话里几乎必然失效：签名覆盖的 jsonl 里包含当前会话自己那份，你每跑一次命令，
这份日志就长一截，签名必变。这是对的——数据真的变了，就该重算。

要验证缓存层本身没坏，把两次调用放进同一条命令跑，期间日志不动，第二次就会显示命中：

```bash
python scripts/quota_report.py && python scripts/quota_report.py
```

## 五、唯一写盘的地方

脚本对会话日志只读。所有写入都在 `%LOCALAPPDATA%\quota-pill\` 下：

| 文件 | 谁写 | 作用 |
|---|---|---|
| `skill-cache.json` | `quota_report.py` | 签名缓存，删掉只是下次重扫 |
| `notify-state.json` | `notify.py` | 同一模型同一等级的 2 小时冷却 |
| `runtime\` | `install_task.py` | 提醒脚本的运行副本 |

删掉整个目录不会损坏任何功能。

## 六、和托盘版的边界

| | 托盘版 | 技能版 |
|---|---|---|
| 形态 | 常驻小窗，开机自启 | 只在提问时被唤起 |
| 谁渲染 | 自己用 Tk 画三态 | 宿主渲染 Markdown |
| 输入框避让 | GDI 像素带探测 | 没有，也不需要 |
| 数据层 | 同一份 `quota_watch.py` | 同一份，逐字节 |
| 提醒 | 内置 | 可选附件，靠计划任务 |
| 单次成本 | 常驻内存 + 定时刷新 | 0.04 秒命中缓存 / 0.8 秒重扫 |

数据层共用同一份实现，所以两边算出来的数必然一致——这是「报告和托盘窗口对得上」的原因，
也是 `sync_check.py` 用哈希守着的理由。

提醒是唯一会改变系统状态的部分，它按两个条件二选一触发：**任一模型已用 ≥80%**，或
**预计 1 小时内触限**。这两个条件与报告底部那行「注意」（只认 `level=critical`）口径
不同——提醒是「要不要现在叫你」的阈值策略，报告是「有没有风险」的判定结论，前者可以更宽。
阈值都能改（`--pct` / `--warn`），但改了要重新注册任务才生效。

## 七、已知失效模式

每一条都在真机或异机上出过，不是假想：

1. **相对路径调用** → `can't open file 'scripts/quota_report.py'`。必须用绝对路径。
2. **把 `reset_at` 当数字算** → 整列重置时间变空。它是字符串。
3. **拿低置信度的增速反推结论** → 说出「按这个速度并非撑不到，而是早就触发了上限」这种
   自相矛盾的话。低置信度的增速就是噪声，只能说明样本不足。
4. **把「表里只有一个模型」说成「只统计了当前会话」** → 扫描范围是全部历史会话。
5. **`schtasks.exe` 被客户端的程序黑名单拦** → 进程根本起不来（1 毫秒内 `WinError 5`）。
   两台互不相关的机器表现一致，说明这是宿主沙箱自带的策略，不是某台机器的安全设置。
   降级到 PowerShell 的 ScheduledTasks 模块可以正常注册，所以降级链是必需品。
6. **「第二次还是重新扫描」被误判为缓存坏了** → 见第四节，这是正确行为。

## 八、没有做的事

- **增量读日志**：每次全量扫。日志大了会慢，靠缓存兜，而缓存经常失效。
- **历史库**：不落库、不累积，每次都从原始日志重算。跨周期对比只能靠翻日志。
- **跨平台验证**：查询层没写死 Windows API（就是 glob + json），理论上能跑；
  提醒层用了 WinRT toast 和任务计划程序，是 Windows 专有。没测过的一律不声称支持。
- **`allowed-tools` 粒度**：`Bash(python:*)` 是否真的只放行了 python，没验过。
- **多技能竞争的触发**：同时装积分、用量类技能时「额度」这个词归谁，没测过。
